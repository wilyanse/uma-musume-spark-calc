## Summary
The API now emits `RosterVeteran.hasLowConfidence`, derived on read from the current `capture_fields` status (any `low_confidence`, dismissed-but-uncorrected included), while `minConfidence` stays the raw minimum score. The engine's confidence-only gate follows the flag (true excludes even at ≥ 0.9; false passes even below 0.9); legacy rows without the flag keep the strict `minConfidence ≥ 0.9` gate, and every other exclusion is unchanged. A new engine export `TRAINING_ELIGIBILITY_POLICY = 'capture-status-v1'` is bound into web fit records (v3), browser-local overridden model envelopes (v2) and rank provenance, so fits made under the old policy are refitted once without relabelling `training-v2`. ADR-0003 records the user's approved policy; 01 §9 and 50 §4 carry narrow errata.

## Decisions
- **Derived, not stored.** `has_low` is an `EXISTS` subquery inside the existing veteran SELECT (roster: 5 queries + stamp unchanged; detail: same batch). No migration, no statement-budget change, and it cannot go stale across ingest, resolve, owner-block remap or delete (63 preference).
- **Review status is ignored.** Only field status counts, so a dismissed item over an uncorrected field keeps `true`. In the current code an item is dismissed only by re-ingest (field re-read; flag follows the new fields) or by remap (field dropped with its spark); tests also cover an out-of-band dismissal (direct D1 update, labelled as such).
- **ETag.** No ETag formula change: every flag-changing write (ingest, resolve incl. remap) updates the veteran row and bumps the roster revision (migration 0002). The test asserts the ETag moves on resolve and a stale `If-None-Match` gets 200.
- **Policy is separate from the rules fingerprint.** Folding it into the T15c context fingerprint would orphan stored browser-local overrides (`baseFingerprint`) although no rule changed. It is carried as its own field in every reuse record and checked by the worker at rank.
- **Old records migrate by reading, not rewriting.** v2 FitRecords and v1 local envelopes stay parseable with `eligibilityPolicy: null` (an unknown policy, never guessed), giving one visible refit reason `eligibility-changed` instead of a "corrupt" state.
- **Cross-module regression uses the real engine source** from the API test via a runtime `import(new URL(...))` (test-only; avoids pulling engine sources into the Workers-lib typecheck and avoids a new package dependency). A mutation check (engine gate reverted to the numeric rule) made 4 of the 12 API tests fail, proving the test reaches the engine code (output below).
- **Retained capture payload.** `~/.hermes/cache/scratch/IR1/mcqueen-agent.json` was inspected before reuse: 190 fields, all `ok`, raw min 0.875 (`/sparks/5/sparkId`), next 0.8906 (`/deck/5/cardId`), `/parents/0/isGuest` 0.9 (S2), `masterVersion global-20260930`, `agentVersion "probe"`, no crop keys, fingerprint `a0fbe2ae…`. It is the C# Agent Core assembly of the real screenshot FIXTURES 01–07 + 09/10 from the IR1 audit — a fixture capture, not a real-roster import. Copied verbatim; deterministic edits (low fields, unread parent block) are applied in memory by the tests.
- **Malformed flags** are rejected by the runtime schema and, if they reach the engine anyway, excluded with `malformed hasLowConfidence …` (never coerced).

## Compatibility policy
- Flag absent ⇒ legacy strict 0.9 gate (old rows, older producers, or older schemas that strip unknown keys). This is conservative: such consumers keep excluding accepted < 0.9 captures until they upgrade.
- Every browser refits once after upgrade (server-snapshot reuse via FitRecord v3; local overridden models via envelope v2). Old snapshots stay stored and readable; `training-v1/v2` kinds are never relabelled.
- Fixture/golden rosters carry no flag, so their populations and every golden acceptance number are unchanged (engine 351 tests incl. golden gates pass; files byte-identical, below).
