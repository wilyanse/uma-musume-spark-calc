### F2 — 17 Core tests fail on Windows from pooled SQLite file handles (test harness)
- Tests: `UploadRobustnessTests.Unacknowledged_success_never_deletes_the_veteran` (8 cases), `UploadRobustnessTests.Auth_failures_are_retryable_auth_state_not_dead_letters` (4), `OutboxTests.Malformed_crop_response_keeps_crop_and_blocks_veteran` (3), `OutboxTests.Crop_retry_and_restart_attach_key_to_final_HTTP_body`, `UploadPipelineTests.Crops_upload_first_and_their_keys_land_on_the_right_fields_across_retry_and_restart`.
- Actual: `System.IO.IOException: The process cannot access the file '…\Temp\uma-*.db' because it is being used by another process.` at `UploadRobustnessTests.cs:57` (`File.ReadAllBytes(db)`), `OutboxTests.cs:61/83` (`File.Delete` in `finally`), `UploadPipelineTests.cs:87`.
- Cause: Microsoft.Data.Sqlite pooling keeps the DB open after `Outbox` connections are disposed. Windows refuses the read/delete; macOS/Linux don't. Sibling tests already call `SqliteConnection.ClearAllPools()` first (e.g. `UploadPipelineTests.cs:89`, `Collect.Drop`).
- Smallest suggested fix: call `SqliteConnection.ClearAllPools()` before those reads/deletes. Not implemented. Assertions untouched.
