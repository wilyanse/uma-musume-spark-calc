# 67 — Agent recipient licence/NOTICE delivery (T19)

## Goal
Remove the local recipient-notice packaging gap identified in T16b/T18 independent reviews. Every supported win-x64 self-contained agent publish must deliver accurate applicable licences, copyrights and NOTICE texts for its actual bundled managed/native/runtime components, not merely leave them in NuGet caches or repository inventory. No release is authorized by implementing this task; independent approval, H4 and human publication gates remain.

## Ownership and boundaries
Own agent/legal inventory/texts and deterministic packaging/verification tools; narrowly scoped Windows csproj content/build packaging entries (no application behavior); .github/workflows/agent-release.yml packaging gates and asset paths only if necessary; .github/tests workflow structure/regression checks needed for those changes; agent bundle notice-verification tests/tools; install runbook and task changelog. Read actual package/publish/runtime manifest definitions before edits. No package/framework/runtime upgrades, security suppressions, parser/image/DB/schema/API/browser/master/golden changes, UI/About screen, new service/paid tier, credentials/global config or push/tag/deploy. T16b S8/N6 codec limits remain separate. Correct T16b N7 licence copyright-date metadata from the actual source text without altering upstream texts.

## Requirements
1. Derive inventory from the actual Release win-x64 publish graph, runtime packs and bundle entries, not only direct PackageReferences. Distinguish build/test-only dependencies and optional upstream NOTICE components from code actually shipped. Account for .NET Core and WindowsDesktop/WPF/WinForms self-contained runtime, C#/WinRT/Windows SDK projection, SQLitePCLRaw/native SQLite, Microsoft.Data.Sqlite and all other shipped dependencies including SharpZipLib and Serilog. Retrieve authoritative exact-version nuspec/source/runtime licence and third-party notices; retain source URL/version/hash/provenance. Never invent attribution or treat package metadata alone as recipient delivery. If required rights/texts cannot be retrieved or a licence is incompatible, report a blocker rather than substituting plausible text.
2. Prefer embedding readable notice content as bundled read-only `legal/` data alongside existing extracted app data, preserving the single-EXE distribution contract. Include a readable index mapping components/versions to texts and explaining where to find notices after extraction. Required notices must be accessible to an ordinary recipient without repository, developer tooling, network or NuGet access. If runtime-extracted locations cannot reasonably satisfy accessibility, choose a companion notice archive delivered inseparably with the EXE in one release ZIP, explain the smallest deviation and update workflow/runbook/tests coherently. Do not distribute an EXE alone when obligations rely on a separately optional download. No About UI required.
3. Include applicable full permission/licence/NOTICE texts verbatim. Correctly attribute runtime third-party material, native SQLite public-domain status and Apache package obligations. Retaining broader verbatim upstream NOTICE is acceptable when marked honestly; do not assert optional SQLCipher/OpenSSL ship solely because a upstream repository NOTICE mentions them. Inventory is technical licence evidence, not a legal opinion or blanket approval.
4. Ensure supported local and CI publishes cannot silently omit notices. Verify final delivered artifact bytes/manifest, not just Content entries/source files. Fail closed on missing/truncated/changed text, unresolved shipped dependency/version or inventory drift, with deterministic negative regressions. Verification must follow the actual restored runtime version; do not freeze one host SDK's runtime provenance while CI can resolve another. No stale inventory or undetected runtime/dependency update. Build only dependency/license evidence, never credentials.
5. Keep release tag validation, pinned workflow actions, audit enforcement, self-contained win-x64 target, bundle data15/15, no credentials in command arguments and existing trust checks intact. No real GitHub release calls or cloud operations during testing. Tests may use deterministic mocked release tooling.

Test valid, missing, corrupted and stale dependency/runtime inventory paths; publication remains mocked. Cross-target byte inspection is not Windows startup/extraction or UI acceptance. Document exact commands/output and every scope/deviation choice. Independent read-only review and parent same-candidate gates before merge; maximum two worker fix rounds. H4/native use and actual publication remain separate human gates.
