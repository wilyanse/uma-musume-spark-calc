## 2. Golden dataset (T08): `packages/engine/test/golden/`
Generated by `pnpm --filter engine golden` (seed `20260929`). It's a **synthetic** roster of 260 veterans built from real master-data IDs, with known ground truth planted:
- **Card effects:** 12 specific cards get known per-stat training effects (e.g. `+40 spd at LB4`); the rest are 0 ± noise. Residual noise is MVN with a known covariance.
- **Rules:** the inheritance is generated using `rules.json` values, with an optional multiplier (default 1.0; the calibration test uses 1.3).
- **Modes:** 60% independent / 40% manual, with different intercepts (independent −120 on the total) and different skill-acquire rates.
- **Planted best pair (target `golden-cm-1`: Medium/Turf/Pace, min spd 1100, sta 800, required skill X):** exactly one pair whose sparks (3★ blue stamina, 3★ pink medium, white spark for skill X) make it the unique best.
- **Planted trap pair:** the highest combined blue stars in the roster but no source for skill X.
- The files are `roster.json` (valid `RosterVeteran[]`), `truth.json` (planted parameters), and `targets.json`. `apps/web/fixtures/` symlinks or copies them for fixture mode.

## 4. Evidence
Each milestone gets `docs/changelog/M<n>-evidence.md`, written by the orchestrator. It links the task changelogs and pastes the real command output of a full `pnpm -r test` and `dotnet test` run on the merged `main`.

## 5. Human checkpoints (see 80 §3)
Tests that need the real game, a Windows machine or Cloudflare accounts are *not* faked. They're listed as human checkpoints with an exact procedure.
