# 66 — Agent SQLite dependency security (T18)

## Goal and evidence
Remove the inherited high transitive advisory GHSA-2m69-gcr7-jv3q from agent Core/Windows and the shipped native SQLite library without changing database contracts or capture behavior. Authoritative source: https://github.com/advisories/GHSA-2m69-gcr7-jv3q (API https://api.github.com/advisories/GHSA-2m69-gcr7-jv3q). Fresh API describes SQLite <3.50.2 aggregate-term memory corruption, affected SQLitePCLRaw.lib.e_sqlite3 <=2.1.11 and no first-patched NuGet value. Actual currently resolved native pin2.1.11 comes via Microsoft.Data.Sqlite10.0.3. NuGet indexes offer later2.1.x and3.x options; no replacement version is preselected. Absence from an advisory list is not proof of the embedded native version.

## Selection and behavior
- Inspect actual NuGet/source metadata, exact package dependency graphs, licenses/build targets/frameworks and all-transitive advisories before selecting the smallest compatible patched package set. Prefer a same-major provider/native update or explicit bundle override when justified over wholesale Microsoft.Data.Sqlite upgrades. Do not mix incompatible SQLitePCLRaw core/provider/bundle/native majors casually.
- Prove the actually loaded native engine version/source-id in macOS portable execution, not merely package version. It must satisfy the advisory's >=3.50.2 fix and current authoritative advisories. Retain deterministic engine-version check and meaningful existing DB compatibility tests, not a package-name-only assertion.
- Verify old persisted DB files remain readable and writable with no unintended migration or data loss. Exercise pending/sealed captures, outbox retries/crops/support-card/settings data, unique constraints and transaction behavior through real SQLite, including reopen after writes and failed transactions. Inspect existing Store definitions/usages first; do not invent APIs.

Prefer retaining all-transitive audited build enforcement so future native advisories cannot hide behind direct-only defaults. Do not suppress advisories/warnings; if another unrelated advisory blocks enforcing this, preserve it as an explicit blocker/follow-up rather than broad upgrades or false security-clearance claims.
